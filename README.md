# 宠缘签 · 你家宠物是什么命？

一个移动端优先的主宠缘分娱乐测试 H5。用户上传宠物照片、完成 7 道轻松问题，本地生成 8 种宠物命格之一，并得到可展开的缘分报告、三项趣味指数和一张 1080 × 1920 的可保存分享海报。

项目为零依赖静态站点，不需要构建步骤。照片只在浏览器内存中处理，不会上传到任何服务。

## 启动

需要 Node.js 18 或更高版本。

```powershell
npm start
```

打开 `http://127.0.0.1:4173`。

修改端口：

```powershell
$env:PORT=8080
npm start
```

让同一局域网内的手机访问：

```powershell
$env:HOST='0.0.0.0'
npm start
```

然后使用电脑的局域网 IP 访问。正式投放到手机端时，建议部署到 HTTPS 静态托管；系统分享、剪贴板、部分浏览器的下载体验在 HTTPS 下更稳定。摄像头入口使用原生文件选择器的 `capture` 能力，不调用 `getUserMedia`，当设备不支持直接拍摄时会自动退化为文件选择。

## 测试

```powershell
npm test
```

测试覆盖：题目与命格数据完整性、8 种命格均可达、同答案确定性、固定平局优先级、指数范围、叙事个性化和非法答案拦截。

## 使用流程

1. 首页点击「开始测测我的毛孩子」。
2. 使用「立即拍摄」或「从相册选择」添加照片，可重新拍摄、更换或确认。
3. 确认后显示「正在读取你和它之间的缘分……」，进入 7 道题。
4. 每题选择一个答案，可返回上一题修改。
5. 结果页展示宠物隐藏身份、专属称号、三项指数、个性化缘分解读和完整报告。
6. 点击「生成我的专属命格海报」，可保存 PNG 或调用系统分享。
7. 点击「重测」会二次确认，并清空当前照片与答案，重新开始。

## 评分机制

- 7 道题、每题 4 个选项，每个选项为不同命格累计权重。
- 总分最高的命格成为结果。
- 平局时按固定顺序优先：招财小福星 → 贵人锦鲤 → 治愈系天使 → 快乐能量体 → 守护灵搭子 → 成长导师 → 傲娇富贵主 → 混世魔王。
- 主宠羁绊值、治愈能量值、幸运象征值由另一组选项权重归一化到 0–100。
- 同一组答案始终得到同一命格、同一指数和同一缘签编号。
- 算法完全本地运行，不调用大语言模型或图像识别 API，不使用随机数决定结果。

命格分数、文案、视觉主题和题目都集中在 `data.js` 中，可安全调整娱乐内容。

## 关键文件

- `index.html`：首页、上传、过渡、答题、结果、海报与说明弹窗的页面结构。
- `styles.css`：移动端优先视觉系统、8 种命格主题变量、响应式布局与动效。
- `data.js`：7 道题、8 种命格、权重、结果文案、分享文案和确定性评分函数。
- `app.js`：照片本地压缩、答题流程、结果渲染、报告展开、Canvas 海报、下载与分享回退。
- `server.js`：零依赖本地静态服务器，带 MIME、CSP、路径穿越防护和 404 处理。
- `tests/scoring.test.js`：评分与数据完整性测试。

## 海报与分享

海报使用 Canvas 生成 1080 × 1920 PNG，包含宠物照片、命格名称、专属称号、命格主题配色、共鸣文案、三项指数、缘签编号和产品标识。

- 「保存到手机」使用 PNG Blob + 下载链接，在无法自动保存的移动浏览器中可长按预览图保存。
- 「分享给朋友」优先调用 Web Share API 分享图片文件；不支持时自动下载海报并尝试复制分享文案。
- 每种命格有不同渐变、符号、关键词与背景纹样。

## 隐私说明

- 照片通过 `FileReader` / `createImageBitmap` / Canvas 在本地读取与压缩。
- 不会上传照片，不写入 `localStorage`、`sessionStorage` 或 IndexedDB。
- 关闭或刷新页面后，照片随页面内存释放。
- 在有未完成内容时，桌面浏览器会通过 `beforeunload` 提示离开；不保证所有移动端浏览器都显示该提示。
- 如果自行把项目部署到第三方平台，请检查平台自身的日志与注入脚本策略。

## 功能边界

- 本项目不接入真实图像识别，不做宠物面相或性格识别。
- 报告内容均为娱乐向、积极象征表达，不构成命运、财富、健康或心理诊断，也不预测具体事件。
- 分享不设置强制门槛，不伪造测试人数、成功案例或用户记录。

## 部署到 Cloudflare Pages

项目已经配置好适合 Cloudflare Pages 的构建流程。Cloudflare 每次构建会执行 `npm run build`，只将 `index.html`、`styles.css`、`data.js`、`app.js` 和 `_headers` 输出到 `dist/`，不会公开 `server.js`、测试代码或其他仓库文件。

在 Cloudflare 控制台创建 Pages 项目时填写：

| 配置项 | 值 |
| --- | --- |
| Framework preset | `None` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | 留空 |
| Production branch | 仓库默认分支，通常是 `main` |
| Environment variables | 不需要 |

本地可提前验证生产构建：

```powershell
npm run build
```

成功后会生成 `dist/`。把新增的 `scripts/build.js`、`_headers`、`package.json` 和 `.gitignore` 提交到 GitHub，Cloudflare 即可完成首次部署并在后续推送时自动重新部署。

部署完成后，在 Pages 项目的 **Custom domains** 中绑定 `example.com` 或 `pet.example.com`。如果域名已经接入 Cloudflare，控制台会自动创建所需 DNS 记录；如果没有，需要先在 Cloudflare 添加域名，并把注册商处的 Nameserver 改为 Cloudflare 提供的地址。HTTPS 证书由 Cloudflare 自动签发。

如果使用 Nginx 等自行托管，请把 HTML/CSS/JS 的 MIME 设置为 UTF-8，并参考 `_headers` 配置 CSP 与安全响应头。
